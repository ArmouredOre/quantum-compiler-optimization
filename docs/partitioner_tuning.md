## Findings and recommendation
- **greedy**: block size is capped by `max_block_qubits=8`, so `max_block_gates` >= 32 changes nothing
  (60 blocks / cut 255 on rand_cliffordt_n20, 54 / 272 on rand_cnotpauli_n20). Smaller `max_block_qubits`
  (6) gives more, smaller blocks and larger cuts. Block-size sd is 5-7 gates with many 1-gate blocks.
- **fallback** (contiguous gate chunks): block sizes are even (sd 1.5-3 at 16-48 gates) but the cut is
  2-3x larger at equal block count, and gate reduction grows with block size (0.3% at 16 gates to 14-15% at 192).
- Downstream gate reduction is about 10-12.5% (greedy, any `max_block_gates`) versus up to 15% for
  fallback at 192 gates, because bigger blocks let more gates cancel. Pipeline time rises with block size.
- GHZ circuits are a chain (width 20/40, depth equals gates): partitioning cannot help and no setting
  reduces gates.
- **Recommendation:** keep the default (`greedy`, 64 gates, 8 qubits); `max_block_gates` is not the
  lever for greedy. If gate reduction on large circuits matters more than speed, evaluate fallback
  with 128-192 gates. METIS was unavailable here; rerun the script with pymetis installed.
  Defaults were deliberately not changed because that would shift every other module's numbers.
