## 2. Results (honest reading)

Setup: policies trained on generated 5-qubit circuits; ablation runs use 40k timesteps and 2 seeds (the planned larger budget did not fit the 2-core sandbox; a firmer answer needs more seeds: `make eval-ablations` with `--seeds 0 1 2 3 4 --timesteps 100000`). 40-qubit generalization uses the 3 seeds x 100k policies from #26.

### CR pass on/off
CR does **all** gate-count reduction (6.5-8.7% with CR, exactly 0 without): the agent's moves are reorderings and rotation merges that CR already finds. CR also adds depth reduction: 13.1 / 9.7 / 12.2 / 10.6 % with CR versus 7.5 / 6.9 / 5.5 / 7.7 % without (5-6, 8-12, 16-20, 40 qubits). The Stage 6 reward is about 3x higher with CR on at 5-12 qubits (0.090 vs 0.030 at 5-6 qubits). A CR-trained policy run with CR switched off lands in between (depth 7.6-9.4 %), so the agent is not a substitute for CR.

### Reward-weight sweep
- The **gate-count weight is inert**: "depth only" and "no fidelity term" give bit-identical results, and gate-count reduction is identical for all variants, because with CR on no agent move changes the gate count.
- The baseline weights (1, 1, 0.5, terminal 1) are best or tied for best depth in most buckets, but most gaps to the other variants are 1-3 points and comparable to the 2-seed spread (up to ±3 at 16-20 qubits). The clearest effect is **removing the terminal bonus** (8.0 % vs 12.2 % depth at 16-20 qubits, lowest Stage 6 reward in three of four buckets). Terminal x3 is close to the baseline; fidelity x4 and depth-only are slightly lower. With 2 seeds I would not claim a ranking among the close variants.
- Recommendation: keep the default weights; do not drop the terminal bonus.

### 40-qubit generalization
Depth reduction (mean ± std over 3 seeds, 6 circuits): stub 0.0, CR only 1.0, greedy+CR 7.5 ± 0.4, **PPO+CR 9.3 ± 0.5**, PPO without CR 8.5 ± 0.2; gate reduction 6.7 % (all CR). The ordering matches the 5-20 qubit results, so the 5-qubit policy transfers. `qft_n40` and `ghz_n40` get 0 (as at every smaller size). An 8x larger step budget gave identical circuits at 8x the time (the greedy policy converges within 40 steps).
End to end through `HybridOptimizer` (default trained agent, per-block, verified): mean Stage 6 reward 0.0382 versus 0.0130 for the untrained stand-in; every circuit's output verified, 0 undecided blocks. The trained agent is **not uniformly better**: it loses on `rand_cnotpauli_n40` (0.0451 vs 0.0508).

### Per-backend policies on the benchmarks
Execution-time reduction (%), test backend superconducting / trapped ion, policy trained on superconducting vs trapped ion (3 seeds): 5-6 qubits 5.60 / 4.15 vs 3.45 / 2.68; 8-12: 5.34 / 4.96 vs 2.29 / 1.35; 16-20: 4.36 / 2.90 vs 2.12 / 1.01; 40: 6.16 / 5.30 vs 3.26 / 3.18. **The superconducting-trained policy is better on both backends in every bucket**; the trapped-ion policy does not win even on its own backend. The one-step greedy time heuristic beats both learned policies at 16-20 qubits (5.41 / 5.12) and ties at 40 qubits (6.04 / 5.80). So per-backend specialization is not demonstrated on benchmark circuits, in line with #29's generated-circuit matrix (trapped-ion own-backend wins in only 2 of 7 seeds). Schedules do differ between backends (36-53 % of cases), but the difference is not an improvement. Recommendation: ship one shared policy; revisit per-backend training with larger training circuits or a stronger time signal.

### Big-O
Quadratic in G for a whole-circuit rollout (the one-step lookahead costs O(G) per candidate action; measured slope 2.13), linear in G inside the pipeline because blocks are bounded (O(T·B·G)). The parameter count (626 floats) is independent of circuit size. Cheap fixes are listed in section 10 of the document and were not implemented.

## 3. How to test and deploy
1. This branch sits on top of the Sprint 4 branch (#35/#46). Apply `sprint4.patch` first, then `sprint5.patch`:
   `git checkout -b sprint5/module-a-ablations origin/main && git apply sprint4.patch && git apply sprint5.patch` (or commit the first before applying the second).
2. `pip install -e '.[test]' && python -m pytest -q` (all green here; optional-dependency tests skip).
3. New tests: `tests/test_rl_ablations.py` (15 tests: variant configs, resumable training, evaluation, summaries and tables, 40-qubit bucket, SVG output, generator and committed circuits in sync).
4. Regenerate: `python scripts/gen_circuits_40q.py`; `make eval-ablations`, `make eval-large`, `make eval-backends-bench`, `make bench-scaling` (the first three train or run for tens of minutes; the scripts are resumable and take `--part i/n` to split work).
   `eval_large_generalization.py` reads `docs/rl_training/gen_runs/seed<k>_{cr,nocr}/final.json` (created by `make eval-generalization`).
5. Review: open `docs/sprint5_report_module_a.md` and the three tables; the committed `runs/*/final.json` + `eval/*.json` mean the report can be rebuilt with `--stage report` without retraining.

## 4. How to write further unit tests
- Pure Python only (CI installs `.[test]`). Use tiny configs (`TINY` in `tests/test_rl_ablations.py`: 200 timesteps, 2 circuits, `numeric_backend="python"`).
- New variants: add to `VARIANTS` in `ablation.py`; the existing tests already check that every variant builds a valid config, that slugs are unique, and that weight variants differ from the baseline only in `weights`.
- Summaries: feed `summarize` a hand-built `{variant: {seed: {circuit: metrics}}}` (see `TestSummary.fake`).
- Scripts are tested through the library (`ablation`, `plots`, `generalization`); the generator is loaded with `importlib` (see `_load_script`). Keep long evaluations out of tests.

## 5. Limitations and open items
- Ablations: 2 seeds x 40k steps; differences among close variants are within noise.
- 40-qubit results are not equivalence-checked by the numeric checker (8-qubit cap); the end-to-end run verifies block by block.
- Per-backend policies come from #29 (60k steps); a longer-trained trapped-ion policy might behave differently.
- The Big-O "cheap improvements" (cache `legal_actions`, incremental lookahead, CR restart) are not implemented; the first two are small, safe changes if you want them as a follow-up.
